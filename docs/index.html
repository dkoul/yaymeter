The JMeter paradox

World-class engine. Museum-grade UX.

We're not here to bash JMeter — teams run serious load with it every day. We're here to admit the truth: authoring tests in the desktop UI is painful, and out-of-the-box results read like homework for a stats class. Yaymeter keeps JMeter as the execution engine and removes the misery around it.

Raw JMeter

  • Click through nested trees to build HTTP samplers by hand
  • XML plans that are easy to break and hard to review in PRs
  • JTL files and aggregate graphs — powerful, but cryptic
  • "What failed?" often needs a JMeter guru in the room

Yaymeter

  • Point at openapi.yaml or an MCP server — get a deterministic plan
  • One parametric plan.jmx you can commit and reuse in CI
  • Markdown report: PASS / FAIL / gaps, per operation, no p-values required
  • Safety knobs: host allowlists, --approve for mutations & load

JMeter's cousin, not a replacement. When you need the hammer, Yaymeter still swings it — you just don't have to forge the handle yourself.

What you get today

From spec to evidence — without the suffering

OpenAPI → tests

Positive, negative, boundary, and security-basic cases from your contract. Review plan.json, export JMX, gate in CI.

Real JMeter runs

Portable JRE + JMeter land in .tools/. Same JMX for smoke (1 thread) and load (N threads) — flip properties, not rebuild plans.

Reports for humans

Coverage vs discovered operations, untested endpoints with reasons, load aggregates when you crank threads — not a wall of percentiles unless you want the JTL.

Safety by default

Enforced limits on requests, concurrency, ramp, and error rate. TLS-verified runtime downloads. Tokens via env — never baked into the JMX.

New: MCP

Model Context Protocol servers, same happy path

MCP tools ship with JSON Schema inputs — just like OpenAPI operations. Yaymeter inventories tools/list, plans tool calls and protocol checks, and runs them with the official MCP SDK. JMeter stays for HTTP load; MCP functional runs use --executor mcp.

MCP quick start
pip install -e ".[mcp]"
yaymeter inspect --mcp-url https://your-server/mcp --out mcp-inventory.json
yaymeter plan --inventory mcp-inventory.json --config my-api.yaml --out plan.json
yaymeter run --plan plan.json --config my-api.yaml --executor mcp --approve

Ship it

Three commands to CI

01

Install

pip install -e ".[dev]"
02

Plan & export

yaymeter plan --spec openapi.yaml --config my-api.yaml
yaymeter export-jmx --plan generated-tests/plan.json --config my-api.yaml
03

Run in CI

yaymeter run-jmx --jmx generated-tests/plan.jmx \
  --threads 1 --loops 1 --approve
