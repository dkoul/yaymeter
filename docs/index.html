What Yaymeter does

Contract-driven API testing without the glue work

Yaymeter is a CLI and agent skill that treats your OpenAPI spec as the source of truth. It inventories operations, designs layered cases (positive, negative, boundary, schema checks, simple workflows), validates the plan, and materializes industry-standard JMeter tests you can review, diff, and commit.

📋

Deterministic plans

plan.json is stable and reviewable — not a one-off script. Validate before you run; know exactly what will hit your API.

⚡

One JMX, two modes

The same plan.jmx runs functional smoke (1 thread) and approved load tests (N threads, ramp, loops) via JMeter properties.

🛡️

Safety by default

Host allowlists, explicit --approve for mutations and performance, and config flags so you do not accidentally load production.

📊

Evidence, not vibes

Reports use results.json and JTL — coverage gaps, PASS/FAIL counts, and untested operations with reasons. Metrics are not LLM guesses.

How it works

From spec to green (or actionable red)

Configure base URL and safety once, then iterate on the spec. Yaymeter keeps the pipeline predictable for both manual runs and automation.

1

Inspect

Validate OpenAPI and list operations

2

Plan

Generate plan.json

3

Export

Build plan.jmx for CI

4

Run

JMeter functional or load

5

Report

Coverage + Markdown

Functional smoke

One virtual user — contract and regression checks after deploy.

yaymeter run-jmx --jmx plan.jmx \ --threads 1 --loops 1 --approve

Load (approved)

Same JMX — scale threads, ramp, and loops when config allows performance.

yaymeter run-jmx --jmx plan.jmx \ --threads 25 --ramp-seconds 60 \ --loops 30 --approve
